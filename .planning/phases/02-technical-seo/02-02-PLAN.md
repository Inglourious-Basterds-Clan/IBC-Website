<objective>
Produce the committed share and identity images the head (02-04) and JSON-LD (02-05) will reference: the designed 1200×630 OG card (D-06), the rose-on-dark-tile favicon set (D-08), and the transparent square rose for the Organization logo (D-12). Purpose: SEO-03 needs a real 1200×630 card (the current og:image is the 4.7 MB hero), SEO-04 needs favicons (fixes the pre-existing favicon.ico 404), SEO-05 needs a square logo of at least 112 px. The research flagged sharp 0.35.5 as [SUS] (too new), so a human verifies the package first and the plan pins the older 0.35.4.

Design choice (Claude's discretion, CONTEXT "how the OG card and the favicon set are produced"): sharp lives in an isolated tool package `tools/seo-images/` with its own package.json and lockfile instead of the root devDependencies the research suggested. Reasons: (1) the site's CI `npm ci` never downloads a native image library it does not use (smaller supply-chain surface, T-02-SC); (2) the root package.json stays untouched, so this plan runs in parallel with 02-01 (which edits the build script) and does not collide with Phase 3's planned package.json edits (research Pitfall 10).

Output: tool package + generator, `lib/image-size.js`, six committed images, `test/seo-assets.test.js`.
</objective>

Facts (research, measured with sharp 0.35.5 in a scratch folder on this Windows machine, 2026-10-06):
- src/assets/logo.png is 4608×4500 (not square), transparent, pale-beige low-poly rose. Always resize with `fit: "contain"` and a fully transparent background.
- src/assets/hero-bg.jpg is really a 1920×1080 PNG; sharp reads it by content, not extension.
- sharp renders SVG overlays (text via system fonts through fontconfig/pango). In the probe a long headline overflowed the right edge, which is why this plan adds a pixel-level safe-area check and a human visual check.
- Probe output: a 1200×630 mozjpeg JPEG at quality 82 was 111,020 bytes.
- ICO container (research "ICO container"): 6-byte header (reserved 0, type 1, count), 16-byte entries (width, height, 0 colors, 0 reserved, planes 1, bpp 32, byte size, data offset), then the embedded PNG files; width/height byte 0 means 256.
- Colours: `--bg-primary: #080e11`, `--accent-color: #cbb18a`, `--text-primary: #e8ded0` (src/css/style.css :root).
- .gitignore already ignores `node_modules/` at any depth, so tools/seo-images/node_modules stays out of git.
- 02-01 (same wave) sets `site.ogImage = "/assets/og/og-default-v1.jpg"`; the file name here must match exactly.
