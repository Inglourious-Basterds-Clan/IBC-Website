# Phase 04 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Retroactive contract.** Wave 1 (04-01 join page + breadcrumbs + FAQ markup, 04-02 build safety, 04-03 Discord badge) is already on `main`. This spec records the shipped patterns as the contract and fixes the visual and interaction rules for the remaining waves: 04-04 (`/operacje/` markup), 04-06 (`src/css/partials/pages.css`), 04-07 (nav, teaser, redirect). Plans 04-05 and 04-08 have no visible UI. Phase 5 owns the visual refresh (UI-01..03) and a11y (A11Y-01..05). Phase 4 **adds no new visual effect, no new custom property, no new font and no new colour**. It only arranges existing HUD primitives (RESEARCH Open Question 1, resolved).

**Sources:** 04-CONTEXT.md (D-03..D-17), 04-RESEARCH.md, 04-01/04-03 SUMMARY, 04-04/04-06/04-07 PLAN, shipped code at `51ac7e9` (`src/css/partials/*.css`, `src/jak-dolaczyc.njk`, `src/_data/join.js`, `src/index.njk`, `src/_includes/partials/breadcrumbs.njk`). I measured layout in headless Chrome on the current `_site/` build: fixed header **79 px tall at 1280 px** and **99 px tall at 390 px** (≤ 768 px header). Before 04-06 the breadcrumbs render at top 0, hidden under the header.

## Spacing Scale

Declared values for all new rules in this phase (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | h3 → paragraph gap inside steps, types and timeline items; era tag vertical padding |
| sm | 8px | Era tag horizontal padding and gap; open FAQ summary → answer; recap meta → title → text; breadcrumb separator side margin; step column gap ≤ 768 px |
| md | 16px | FAQ list gap; FAQ item vertical padding; step row padding and column gap; list item left padding; `.page-cta` gap; mobile card padding |
| lg | 24px | FAQ item horizontal padding; h2 → block content; schedule/type/recap grid gap; timeline left padding and step spacing; recap body and `.upcoming` padding; `.upcoming` text → button |
| xl | 32px | Breadcrumbs → first section (`.breadcrumbs + .subpage { padding-top: 32px }`) |
| 2xl | 48px | Between `.page-block`s (`margin-top`); `.page-cta` top margin; step counter column width |
| 3xl | 64px | Not used by new rules. Reserved |

Exceptions (each justified):
- **Fixed-header clearance.** Breadcrumb `padding-top` is **100px** above 768 px (header 79 px + 21 px gap) and **120px** at ≤ 768 px (header 99 px + 21 px gap). This is a layout offset tied to the measured header height, not rhythm spacing. 100 px also matches the existing `section { padding: 100px 20px }`.
- **20px horizontal gutter.** `.breadcrumbs` uses `padding: … 20px …` so the trail lines up with the existing `section` side padding. It is not a new rhythm value.
- **`.recruitment-more { margin-bottom: 20px }` (04-07).** This matches the existing 20 px bottom margins of its siblings `.recruitment-badge` and `.recruitment-lead` in the same card.
- **Inherited, not redeclared:** `.section-header` 60 px bottom margin, `.req-list` 12 px gap, section 100 px vertical padding. These are existing values that Phase 4 does not touch.
- **Touch targets:** no new icon-only controls. The existing header CTA is icon-only at ≤ 480 px and keeps its visually hidden "Discord" label. `summary` rows are ≥ 48 px tall (16 + 24 line + 16 = 56 px total height with padding).

## Typography

Root size 16 px. Every new rule uses only these four sizes and two weights. Headings get `text-transform: uppercase` and `letter-spacing: 1.5px` from the existing global `h1–h6` rule in base.css.

| Role | Size | Weight | Line Height | Used by |
|------|------|--------|-------------|---------|
| Label | 13.6px (0.85rem) | 400 (700 for `.evening-time`) | 1.5 | Breadcrumbs, `.recap-meta`, `.recaps-updated`, `.era-list li`, `.evening-time`, `.discord-badge` (shipped) |
| Body | 16px (1rem) | 400 | 1.6 (existing global `p` rule) | Paragraphs, `.page-lead`, FAQ answers, step and type texts, FAQ `summary` (700), every `h3` in page lists (700, line height 1.2) |
| Heading | 24px (1.5rem) | 700 | 1.2 | `.page-block h2`, join step counters `01–06` |
| Display | 35.2px (2.2rem) | 700 | 1.2 | `.subpage .section-header h1` (the page's only h1) at every viewport, the same size as the existing `.section-header h2` on home |

Rules:
- Today the subpage h1 renders at the browser default of 32 px (measured). 04-06 sets it to 2.2 rem with `color: var(--text-primary)`. It gets no gradient text, because that is an effect and Phase 5 decides effects.
- `.page-lead` stays at Body size 16 px. It stands apart through `opacity: 1` (normal `p` has 0.85) and `max-width: 70ch`. It does not get a fifth size (see PD-3).
- Font families: HUD-flavoured text (breadcrumbs, labels, counters, `summary`, `.evening-time`) uses `var(--font-hud)`. Body copy uses `var(--font-body)`. Both are Montserrat today.
- Glyphs: use only characters in the Montserrat subset (`test/fonts.test.js`). Allowed symbols: `– — … „ ” › → · • »`. Never use `✓ ↗ ⟶` or emoji.

## Interaction Contract

|---------|-----------|
