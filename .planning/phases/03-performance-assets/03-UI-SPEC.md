# Phase 03 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Contract type: PARITY LOCK (retroactive).** This spec was written mid-execution, after plans 03-01 to 03-05 had run on `gsd/phase-03-performance-assets`. Phase 3 changes how assets are delivered (responsive AVIF/WebP images, self-hosted Montserrat, inline SVG icons, one Lightning CSS bundle built from partials, ES modules). It does not change the design. CONTEXT.md D-15 says: "Strict visual parity ... No design changes; those belong to Phase 5."

So this contract has two parts:

1. **Locked baseline.** The existing design system (tokens, type, spacing, color, copy, component states, motion) as it is in `src/css/style.css`, the templates and `src/js/main.js` at HEAD `af325ff`. Plans 03-06 to 03-11 must not change a computed value in this baseline.
2. **New delivery contracts.** The visual and interaction rules Phase 3 adds: the hero `<img>`, `<picture>` loading, the lightbox source swap, the inline SVG icons, the font face and fallback, the state classes that replace inline styles, and the CSS partial split.

The off-scale spacing values and the extra font sizes and weights listed below are **existing debt, frozen on purpose**. Normalising them would be a visible change and would break D-15, so Phase 5 (visual refresh, `/gsd-ui-phase 5`) owns that. Phase 3 must not add a new spacing value, font size, weight or color.

Parity references:
- Phase 1 baseline: `.planning/phases/01-eleventy-foundation/baseline/after/*.png` (root/sub × desktop/mobile × top/about/gallery/recruitment, plus w320-top and w768-top)
- Phase 3 evidence (made by 03-11 Task 3): `.planning/phases/03-performance-assets/parity/{before,after}/*.png`. Before = commit `03ce0de`, after = phase HEAD. There are 15 named shots, listed under "Parity verification" below.

## Spacing Scale

Declared scale. Any spacing value that is genuinely new in Phase 3 must come from this table:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing (`.hud-btn` gap 8px; `.terminal-body` gap 8px) |
| md | 16px | Default element spacing (`.skip-link` horizontal padding 16px) |
| lg | 24px | Section padding (`.hud-btn` horizontal padding 24px) |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks (logo height 48px) |
| 3xl | 64px | Page-level spacing |

The Phase 3 delivery rules add **no spacing at all**: `.hero-img`, `.hero-image-bg::after`, `picture { display: contents }`, `.icon`, `.lightbox.is-open`, `.decryption-overlay.is-open`, `.tag-error` and `.terminal-line-alert` contain no margin, padding or gap.

## Typography

One family renders everywhere: **Montserrat** (both `--font-hud` and `--font-body`). The stacks are locked as:
- `--font-hud: 'Montserrat', 'Montserrat Fallback', monospace;`
- `--font-body: 'Montserrat', 'Montserrat Fallback', sans-serif;`

Inter and Share Tech Mono were never rendered and are removed (D-07). The final HUD/mono face is a Phase 5 decision.

Primary roles (the four roles a reviewer should check first):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (1rem, inherited; `p`) | 400 | 1.6 |
| Label | 13.6px (0.85rem; `.stat-card p`, footer links, `.terminal-header` at 0.8rem) | 400 | normal (≈1.22 for Montserrat) |
| Heading | 35.2px (2.2rem; `.section-header h2`; 28.8px / 1.8rem at ≤768px) | 700 (UA bold for h1–h6) | normal (≈1.22) |
| Display | 56px (3.5rem; `.hero-text h1`; 40px / 2.5rem at ≤768px) | 700 (UA bold) | 1.1 |

Primary weight pair: **400 regular + 700 bold**.

Locked exceptions (existing, frozen under D-15; Phase 3 adds none and removes none, apart from dead-CSS removal):
- **Weights 800 and 900**: only the header logo wordmark (`.logo-text span` 800; the second span 900). Weight 500 exists only in dead CSS (`.status-item .value`), and 03-10 deletes it.
- **Other sizes in use**, unchanged: 0.72rem (logo wordmark), 0.75rem (`.hud-badge`, `.copyright`), 0.8rem (`.header-cta`, gallery overlay `p`, `.terminal-header`), 0.9rem (`.terminal-body`), 0.95rem (nav links, `.section-header p`, `.highlight-box p`, `.decryption-content`, `.recruitment-lead`), 1.05rem (`.about-content p`), 1.1rem (`.hero-text p`, gallery overlay `h3`, `.recruitment-cta`), 1.2rem (lightbox nav, `.decryption-header`), 1.3rem (`.about-heading`, `.recruitment-heading`, `.recruitment-cta-icon`), 1.5rem (`.recruitment-info h3`, `.footer-logo`, `.lightbox-close`), 1.8rem (`.stat-text`), 2.5rem (`.stat-card h3`).
- **Other line heights**: 1.1 (`.logo-text`), 1.8 (`.decryption-content`). `.recruitment-lead` keeps 1.6.
- **Letter spacing and case (locked)**: h1–h6 1.5px uppercase; `.hud-btn` 2px uppercase; nav links 1px uppercase; `.footer-logo` 2px.
- **Italic**: `.highlight-box p` stays a *synthesised* italic. No italic font file is added.
- **Gradient text (locked)**: `h1 span, .section-header h2, .logo span` use `linear-gradient(178.76deg, #F3EDE3 20.92%, #E8DED0 62.03%, #DACAB3 80.5%)` with `background-clip: text`. The `-webkit-background-clip` and `-webkit-text-fill-color` prefixes must survive bundling.

Font delivery contract (new in Phase 3, shipped in 03-05):
- `@font-face "Montserrat"`: `src: url("../fonts/montserrat-latin-ext.var.woff2") format("woff2")`, `font-weight: 100 900`, `font-display: swap`, `unicode-range: U+0000-00FF, U+0100-017F, U+2000-206F, U+20AC, U+2122, U+2190-2193, U+2212`.
- `@font-face "Montserrat Fallback"`: `local("Arial")`, `size-adjust: 110.38%`, `ascent-override: 87.70%`, `descent-override: 22.74%`, `line-gap-override: 0%`. While the font loads, text renders right away in the fallback face. The swap must not visibly reflow headings or buttons (CLS stays 25/25). If the parity screenshots show a fallback-induced difference, drop the fallback face rather than change any size (research A4).
- The head contains exactly one `<link rel="preload" as="font" type="font/woff2" crossorigin>`, placed before the stylesheet.
- Polish glyph coverage `ą ć ę ł ń ó ś ź ż Ą Ć Ę Ł Ń Ó Ś Ź Ż` is machine-checked (D-10). The visual check uses "Zażółć gęślą jaźń" on `/_dev/font-test/` (03-11) at h1, h2, h3, p, strong, `.hud-btn` and `.hud-badge.amber`.
- Accepted difference: tiny sub-pixel rendering differences between Google-served and self-hosted Montserrat (D-15).

## Delivery Contracts (new in Phase 3)

### Hero image (PERF-02, D-03, shipped in 03-01)
- Markup: `.hero-image-bg > picture > img.hero-img`, `alt=""`, `sizes="100vw"`, `loading="eager"`, `fetchpriority="high"`, `decoding="async"`, widths 640/960/1280/1920, AVIF + WebP sources + JPEG `src`.
- Framing: `.hero-img { width:100%; height:100%; object-fit:cover; object-position:center; display:block }` reproduces the old `background-size: cover; background-position: center`. No art direction and no mobile crop (deferred to Phase 5).
- Overlay: `.hero-image-bg::after` with `linear-gradient(rgba(8,14,17,0.35), rgba(8,14,17,0.75))`, inset 0, above the image.
- Loading state: the hero text and buttons render right away over the `.hero` radial-gradient background. The image appears when decoded, with no fade, blur-up, placeholder or skeleton (none existed before).
- Preload: home page only. One typed AVIF `<link rel="preload" as="image" type="image/avif" fetchpriority="high" imagesizes="100vw" imagesrcset=…>`. `imagesizes` must equal the `<img sizes>`.
- Accepted parity deviation: on a 3× portrait phone the hero may be slightly softer than the 1920 px original, under the dark gradient (research Pitfall 9). Do not raise `sizes` to chase sharpness.

### Responsive `<picture>` (PERF-01, shipped in 03-01 and 03-04)
- `picture { display: contents }`. Wrapping an `<img>` must never change layout; the `<img>` keeps its existing selector box.
- Every `<img>` carries `width` and `height`, the intrinsic size of the largest variant, used for the aspect ratio. The CSS box (`.gallery-item img` 100%/100% cover, `.logo-img` 48px/auto, `.hero-img` 100%/100%) wins over the attributes.
- Gallery thumbnails: `loading="lazy"`, `decoding="async"`, `sizes="auto, (min-width: 1240px) 285px, (min-width: 660px) 50vw, 100vw"`, widths 400/600/900/1200. Loading state: the tile's `.hud-border` surface and the overlay title show until the image decodes. No skeleton or shimmer is added.
- Only the hero is eager. Everything else is `loading="lazy"`, including the header logo (03-04 decision).

### Lightbox image swap (PERF-03, D-04, shipped in 03-04, state class in 03-09)
- The shipped `<picture class="lightbox-picture">` has no `<source>` and no `src`, so nothing downloads before the first open.
- First open: insert `<source type="image/avif">` and `<source type="image/webp">` before the `<img>`. Every open or navigation sets the AVIF `srcset`, then the WebP `srcset`, then `img.src` (JPEG) last. Each target is 1600 w and under 300 KB.
- `.lightbox-content img { width:auto; height:auto; max-width:100%; max-height:80vh; object-fit:contain }`. The `width="1600" height="900"` attributes supply only the aspect ratio, so the frame shape is the same as before (Pitfall 6).
- Loading state: no spinner. The frame and caption update at once and the image paints when decoded (existing behaviour).
- Open state: `#lightbox.is-open` → `display:flex`. The arrow and Escape keys act only while `.is-open` is present. The click-outside target is the `#lightbox` backdrop. Scroll lock: open sets `body.style.overflow='hidden'`, close sets it to `'auto'` (existing, unchanged).

### Inline SVG icons (PERF-05, D-11, plan 03-07)
- Markup (single line): `<svg class="icon icon-{name}[ {extraClass}]" aria-hidden="true" focusable="false" viewBox="{viewBox}" fill="currentColor"><path d="…"/></svg>`. viewBoxes: discord `0 0 640 512`, youtube `0 0 576 512`, facebook `0 0 512 512`.
- Sizing: `.icon { display:inline-block; height:1em; overflow:visible; vertical-align:-0.125em }`. This is Font Awesome's own `.svg-inline--fa` rule, so glyph, size and baseline match the old webfont. Width follows the viewBox (Discord 1.25em, YouTube 1.125em, Facebook 1em).
- Rendered sizes come from the parent `font-size`, unchanged: header CTA 0.8rem (12.8px); `.hud-btn` on 404 1rem (16px); footer `.social-icon` 16px inside the 40×40 box; recruitment button 1.3rem (20.8px) through `.recruitment-cta-icon`. Gaps come from the parent: `.hud-btn` 8px, `.recruitment-cta` 10px.
- Color: `currentColor`, so icons follow the link color in every state (accent at rest on buttons, `--text-secondary` → accent on social-icon hover, `--bg-primary` on `.hud-btn.active`).
- Accessibility: every SVG is `aria-hidden="true" focusable="false"`. The accessible name sits on the link: `aria-label` on the footer icon-only links (Discord, YouTube, Facebook), visible or visually hidden text elsewhere. Each link is announced exactly once by name. An unknown icon name fails the build, and the build never emits empty markup.
- No `fa-`/`fab` classes, no cdnjs and no Font Awesome URL anywhere in the output.

### State classes replacing inline styles (PERF-06/07, D-12, plans 03-08 and 03-09)
- Built HTML contains zero `style=` attributes and no `<style>` element.
- Runtime state is written as classes only: `.lightbox.is-open`, `.decryption-overlay.is-open`, `.terminal-line .tag-error`, `.terminal-line-alert` (+ `.tag` / `.message`). Existing state classes keep their names: `nav ul.active`, `.menu-toggle.open`, `a.active-nav`. Exception: the `body.style.overflow` scroll lock is runtime-only, never in the HTML, and kept as is.
- Every converted class must reproduce the old inline declarations exactly and win the cascade the way the inline style did (an ancestor class raises specificity where needed).

### Stylesheet structure (PERF-06, D-12/D-13, plans 03-08 and 03-10)
- Exactly one `<link rel="stylesheet">` per page, minified, `?v=` content hash.
- 03-10 splits `src/css/style.css` into an `@import` entry plus 10 partials in today's cascade order: fonts, base, components, header, hero, sections, gallery, recruitment, footer, responsive. The bundled output must stay **byte-identical** before and after the cut, checked with `cmp` for each partial, before dead CSS is deleted. Then dead selectors are deleted (roster, calendar, status panel, countdown/timer, form styles, `.hud-badge.green`/`.danger`, all-dead responsive rules). No live selector's computed style may change.
- `url()` in partials is written relative to the output `/css/style.css`.

### Feature loading (PERF-07, D-14, plan 03-09)
- Hooks: `data-js="menu"` (`.menu-toggle`), `"scroll-spy"` (`<nav>`), `"lightbox"` (`.gallery-grid`), `"terminal"` (`#terminal-console`), `"easter-egg"` (`#easteregg-trigger`).
- No visible difference from the classic script. Module scripts are deferred, as `DOMContentLoaded` was. Nothing is interactive before the module loads that was interactive before. The terminal still boots only on intersection.
- Pages without a feature (404, dev pages) never fetch that module and show no console errors.
